# 자이제 1·2·3 문서 기반 QA 데이터셋

자이제 1·2·3의 원문에서 각각 150개씩 생성한 **총 450문항**이다.
질문·기준답변·근거 원문·페이지·장·절·Excel 행 번호를 포함한다.

**다운로드: [CSV](final_450/qa_dataset.csv) · [JSONL](final_450/qa_dataset.jsonl)**

| 원문 | 사용 시트 | 본문 열 | 문항 |
|---|---|---|---:|
| 자이제_1.xlsx | clean_sentences | text_for_llm_human | 150 |
| 자이제_2.xlsx | 종학 파트 | 사람 검수 | 150 |
| 자이제_3.xlsx | clean_sentences | 사람 검수 | 150 |

모델은 `gpt-5.6-terra`, 프롬프트 버전은 `jaije-qa-v1`이다.
같은 절의 원문을 최대 18행·5,000자로 묶어 호출당 최대 3문항을 생성했다.
자이제 2·3의 빈 검수 셀은 제외했다. 세 파일에는 같은 프롬프트와 five-shot을 사용했다.

## 생성 프롬프트

실제 [시스템 프롬프트 원본](jaije2_3/prompts/system_prompt.txt)의 핵심 요약:

```text
역할: 한국어 수주·제안 분야의 검증용 QA 데이터셋 큐레이터
제공된 SOURCE_RECORDS만 사용해 실무자가 물을 법한 질문과 기준 답변을 만든다.
질문은 원문 없이도 이해할 수 있어야 하며, 질문에 정답을 노출하지 않는다.
답변은 원문에 직접 근거한 한국어 1~2문장으로 작성한다.
답변을 지지하는 최소한의 근거 행 1~4개를 source_row_ids로 선택한다.
외부 지식이나 원문에 없는 인과관계·순서·의무 등을 추가하지 않는다.
중복 질문을 피하고 사실·수치·정의·이유·방법·비교·절차·오해 교정 유형을 다양화한다.
근거가 부족하면 요청한 개수보다 적게 반환한다.
출력 필드: question, answer, source_row_ids, question_type, difficulty
```

매 호출의 마지막 사용자 프롬프트:

```text
chunk_id={CHUNK-ID}
아래 SOURCE_RECORDS에서 최대 {target_count}개의 QA를 생성하세요. 충분히 근거가 있는 문항만 반환하세요.

SOURCE_RECORDS:
{같은 절의 원문 행 JSON 배열}
```

각 원문 행에는 행 ID, 페이지, 장·절 정보와 본문이 들어간다.
모델이 선택한 행 ID로 코드가 실제 근거 문장과 출처를 복원한다.

## 실제 five-shot

아래 다섯 예시를 매 호출에 사용자 원문 → assistant 정답 순서로 제공했다.
표의 답변은 핵심 요약이며, 입력 원문·정답 전문·행 ID는
[few_shot_examples.json](jaije2_3/prompts/few_shot_examples.json)에 있다.
예시는 자이제 1에서 가져왔고, 예시 원문은 생성 대상에서 제외했다.

| 유형 | 실제 예시 질문 | 답변 핵심 |
|---|---|---|
| 수치 | RFP 요구조건을 100% 충족한 제안서의 성공률은 얼마인가요? | 쉬플리 조사에서 52%. |
| 복수 근거·오해 교정 | RFP에 적힌 요구조건만 충족하면 고객의 니즈 전체를 반영한 것인가요? | 공식 요구조건 외에 비공식 요구조건도 포함해야 함. |
| 절차·정의 | Bid Validation Decision은 언제 무엇을 확인하는 결정인가요? | RFP 발행 후 승리 가능성을 최종 검토해 참여 타당성을 확인. |
| 비교 | 분석적 평가자와 통합적 평가자는 평가 방식과 배경에서 어떻게 다른가요? | 분석적 평가자는 항목별 집계·내용 전문가, 통합적 평가자는 총점 우선 배분·행정가 또는 사용자. |
| 표 근거·오해 교정 | 제안서는 분량이 많을수록 좋은가요? | 맹목적으로 늘리면 평가를 어렵게 해 부정적일 수 있음. |

요청 순서는 **시스템 프롬프트 → five-shot 5쌍 → 현재 원문 청크**다.
