# TRACE-OL 자이제 파일럿 실험 보고서

## 1. 먼저 결론

이 실험은 자이제 문서를 지식그래프로 만드는 여러 방법을 직접 비교한 파일럿이다.

핵심 결론은 다음과 같다.

1. **문장에서 바로 triple을 만드는 것보다, 문장의 의미를 Claim으로 먼저 정리하는 방법이 더 좋았다.**
2. **어려운 문장만 LLM에 보내는 방법은 시도했지만, 성능 개선을 확인하지 못했다.**
3. **LLM의 교정을 재사용 규칙으로 만드는 방법도 이번에는 작동하지 않았다.**
4. **그래프의 지식을 원문까지 추적할 수 있는 구조는 파일 기준 검증을 통과했다. 다만 실제 Neo4j 서버 로드는 권한 문제로 실행하지 못했다.**

전체 실험은 완료했지만 성공 기준 9개 중 4개만 통과했다. 따라서 최종 판정은 **현재 방법을 그대로 확대하지 말고 수정해야 한다**는 `STOP_OR_REVISE`이다.

- 실험에 사용한 표본: 180건

표본은 다음 6개 유형을 고르게 포함하도록 뽑았다.

- 의무·금지·권고
- 조건·예외
- 절차·의사결정
- 표·수식·평가
- 예시·질문·인용 등 해석이 어려운 문장

180건은 다음과 같이 나누었다.

| 구분 | 건수 | 용도 |
|---|---:|---|
| CAL | 60 | 기본 규칙과 평가 절차 확인 |

B2는 최종 시험용 데이터이다. B2 결과를 본 후에 방법을 수정하지 않도록 표본 ID를 먼저 잠그고 실험했다. 같은 표·섹션·중복 문장이 다른 split에 들어가는 데이터 누출도 0건이었다.

## 3. 성능 비교용 임시 정답은 어떻게 만들었는가

인간 전문가가 만든 정답이 없었기 때문에, 여러 LLM의 독립 분석 결과를 합쳐 `TRACE-LLM-Silver-v0.1`이라는 임시 정답을 만들었다.

1. LLM A와 B가 180건을 서로의 결과를 보지 않고 각각 분석했다.
2. A와 B가 주장 유형, 의무·금지, 부정, 조건, 그래프 사용 여부에서 일치한 결과를 Silver-A로 정했다.
3. A와 B가 다른 경우 LLM C가 다시 분석했다.
4. A·B·C 중 두 개 이상이 같은 답을 낸 결과를 Silver-B로 정했다.
5. 그래도 해결되지 않은 고위험 사례 1건은 더 강한 LLM D가 판정했다.
6. 끝까지 확실하지 않은 결과는 Challenge로 분리했다.

| 임시 정답 구분 | 건수 | 의미 |
|---|---:|---|
| Silver-A | 69 | A와 B가 중요 항목에서 일치 |
| Silver-B | 39 | C 또는 D를 포함해 해결 |
| Challenge | 72 | 안정적으로 결정하지 못함 |

전체 180건 중 108건만 임시 정답으로 확정했다. 따라서 해결률은 60%, Challenge 비율은 40%다.

**중요:** 이 임시 정답은 인간 정답이 아니다. 본 보고서의 점수는 절대적인 정확도가 아니라 **LLM 임시 정답과의 일치도**다.

## 4. 비교한 방법

| 방법 | 설명 |
|---|---|
| E0 | 문장에서 바로 subject-predicate-object triple을 추출 |
| E1 | 문장의 의미를 Claim으로 먼저 정리한 후 그래프로 변환 |
| E2 | LLM 없이 미리 정한 문장 규칙으로 Claim을 추출 |
| E3 | E2 결과 중 어렵거나 위험한 것만 LLM이 검토 |
| E4 | E3에서 확인한 LLM 교정을 재사용 규칙으로 만들어 B2에 적용 |

Claim은 문장을 그래프로 변환하기 전에 의미를 정리한 중간 기록이다. 예를 들어 다음 문장을 보자.

> 계약 금액이 10억 원을 초과하는 경우, 제안팀은 반드시 법무 검토를 받아야 한다.

Claim-first 방법은 이 문장에서 다음을 따로 기록한다.

```text
주체: 제안팀
행위: 법무 검토를 받는다
조건: 계약 금액이 10억 원을 초과하는 경우
의무: 반드시 수행해야 함
원문 근거: 해당 문장의 정확한 위치
```

이 중간 단계를 두면 조건, 의무, 금지, 부정이 triple 변환 과정에서 빠지는 문제를 줄일 수 있다.

## 5. 실험 1: 바로 triple 추출과 Claim-first 비교

### 실제로 한 일

B2 60건에 대해 E0과 E1을 각각 실행했다. 임시 정답으로 안정적으로 해결된 30건만 성능 계산에 사용했다.

### 결과

| 방법 | Claim F1 | 중요 의미 오류율 |
|---|---:|---:|
| E0 바로 triple 추출 | 0.7843 | 0.9000 |
| E1 Claim-first | **0.9310** | **0.4074** |

Claim F1은 1에 가까울수록 임시 정답과 비슷하다는 뜻이다. 중요 의미 오류율은 낮을수록 좋다.

E1은 E0보다 Claim F1이 높았고, 의무·부정·조건 등의 오류율을 약 54.7% 줄였다.

### 해석

**Claim-first 방법이 바로 triple을 추출하는 방법보다 유리했다.** 다만 인간 정답이 아닌 LLM 임시 정답을 사용했고, 평가 건수도 30건이므로 잠정적 결론이다.

## 6. 실험 2: 어려운 결과만 LLM이 검토하는 E3

### 실제로 한 일

E2가 규칙으로 만든 Claim 중 다음에 해당하는 것만 선택했다.

- 규칙의 확신이 낮은 결과
- 의무·금지·부정·조건처럼 오류 영향이 큰 결과
- 그래프에서 중요한 관계가 될 가능성이 큰 결과

B1a에서 6개를 선택해 LLM에 보냈다.

### 결과

LLM은 6개 모두를 `needs_review`, 즉 확실히 승인하기 어렵다고 판정했다. 따라서 확정된 교정 결과를 얻지 못했다.

### 해석

LLM을 전체 문장이 아닌 6개에만 사용하는 절차는 작동했다. 하지만 실제 품질 개선은 없었으므로 **E3가 비용 대비 품질을 높였다고 결론낼 수 없다.**

## 7. 실험 3: LLM 교정을 규칙으로 재사용하는 E4

### 실제로 하려고 한 일

```text
E3의 확정된 LLM 교정
        ↓
반복되는 교정을 재사용 규칙으로 만듦
        ↓
B1에서 규칙 정확도 검증
        ↓
검증을 통과한 규칙을 B2에 적용
        ↓
나머지 어려운 결과만 LLM에 문의
```

### 실제 결과

E3에서 확실하게 승인된 교정이 0개였다. 따라서 만든 재사용 규칙도 0개였다.

B2에서는 검토가 필요한 9개를 LLM에 보냈고 1개를 승인받았지만, 최종 성능 점수는 바뀌지 않았다.

| 방법 | Claim F1 |
|---|---:|
| E2 규칙 기반 | 0.5902 |
| E4 규칙+선택적 LLM+재사용 규칙 | 0.5902 |

### 해석

재사용할 규칙을 만들지 못했기 때문에 E4와 E2의 성능이 같았다. **이번 파일럿은 E4의 효과를 입증하지 못했다.**

## 8. 실험 4: 그래프의 지식을 원문까지 추적할 수 있는가

최종 그래프 관계가 어떤 원문에서 나왔는지 확인할 수 있도록 다음 경로를 저장했다.

```text
원문 Evidence
    ↓
해석된 Claim
    ↓
검증된 Assertion
    ↓
실제 지식그래프 관계
```

원문 근거가 없거나 `NEEDS_REVIEW`인 Claim, 또는 질문·예시·인용을 일반 사실로 잘못 해석한 Claim은 실제 그래프 관계로 사용하지 않았다.

### 결과

- 원문이 없는 승인 Claim: 0건
- Claim이 없는 Assertion: 0건
- `NEEDS_REVIEW`의 실제 그래프 승격: 0건
- 질문·예시·인용의 잘못된 승격: 0건
- 원문까지의 추적 경로 보존율: 100%
- 사전 정의 질문: 10개 중 8개 통과
- Neo4j CSV 구조 검증: PASS

### 해석

파일과 연결 구조를 기준으로는 그래프의 지식을 원문까지 추적할 수 있었다. 다만 Docker 권한 문제로 실제 Neo4j 서버에 로드하지 못했다. 따라서 **정적 검증은 통과했지만 실제 DB 실행 검증은 남아 있다.**

## 11. 왜 STOP_OR_REVISE인가

| 항목 | 목표 | 실제 | 판정 |
|---|---:|---:|---|
| 임시 정답으로 해결된 표본 | 80% 이상 | 60% | 미통과 |
| Challenge 비율 | 20% 이하 | 40% | 미통과 |
| 원문 위치 표시 정확도 | 98% 이상 | 96.38% | 미통과 |
| E1의 중요 오류 감소 | 30% 이상 | 54.7% | 통과 |
| E4가 E1에 가까운 성능 | 차이 0.05 이하 | 차이 0.1836 | 미통과 |
| E4/E1 token 비율 | 40% 이하 | 15.97% | 통과 |
| 재사용 규칙으로 LLM call 감소 | 20% 이상 | 0% | 미통과 |
| 원문 추적 경로 | 100% | 100% | 통과 |
| 지식그래프 질문 | 10개 중 8개 이상 | 8개 | 통과 |

성공 기준 9개 중 4개만 통과했다. 실험이 미완료된 것이 아니라, **완료한 파일럿의 결과가 현재 방법을 수정해야 한다고 나온 것**이다.

## 12. 다음 실험에서 바꿔야 할 것

1. 적은 수라도 전문가가 LLM 결과를 보지 않고 만든 인간 정답을 추가한다.
2. A·B·C가 원문 위치, 조건, 의무, 금지를 더 일관되게 표시하도록 임시 정답 생성 절차를 고친다.
3. E3가 교정할 수 있는 정보를 더 명확히 제공해, 모든 결과가 `needs_review`로 남는 문제를 개선한다.
4. 수정된 방법을 평가할 때는 이미 결과를 확인한 현 B2 대신 새로운 최종 평가 데이터를 사용한다.
5. Neo4j 권한을 확보한 후 생성된 CSV와 Cypher를 실제 DB에 로드해 검증한다.

## 16. Modality 안전성 보완 실험 v2.2

v2.1에서 Claim F1은 상승했지만 modality 오류가 늘어난 문제를 보완했다. v2.2에서는 claim family나 polarity 하나만 맞히는 LF를 자동 적용하지 않고, claim type·modality·polarity·promotion이 함께 검증된 패키지만 사용했다.

- 새 validation 50건, fresh test 50건
- 이전 510건과 evidence 중복: 0건
- 후보 패키지: 7개
- validation 통과: 질문형 패키지 1개
- validation에서 차단: 6개
- fresh test에서 자동 교정을 보류한 행: 6건
- 통과 패키지 fresh-test precision: 100%, coverage 15.15%

- critical error rate: 0.2759 → 0.2759
