## 슬라이드 1. 문제와 접근 — 세부 요구로 후보를 넓히고, 원문으로 근거를 고른다

### 핵심 메시지

최종 방법론은 **PARS-RF + Kiwi**다. 질문의 세부 요구인 Aspect를 후보 검색에 활용하고, 원 질문과 원문의 직접 관련성으로 최종 근거를 선택한다.

### 연구 문제

수주·제안 질문에는 진행 방식, 특성, 조건 등 여러 정보 요구가 함께 들어갈 수 있다. 전체 질문으로 찾은 원문만으로 모든 요구를 충족한다고 보장하기 어렵다는 점이 설계 동기다.

### 질문 예시

> 제안은 어떤 방식으로 진행할 수 있으며, 갖춰야 할 두 가지 특성은 무엇인가요?

정보 요구는 **진행 방식**과 **요구 특성**으로 구분된다.

### 세 구성요소의 역할

| 구성요소 | 역할 |
| --- | --- |
| Aspect | 원문 요구와 조건을 보존하고 요구별 후보 검색 경로를 추가 |
| 업무 그래프 | PCF·TaskFrame으로 관련성을 약하게 보정하고 직접 Fact·속성 뷰를 활용 |
| 원문 재정렬 | 질문–원문 Cross-Encoder로 Top5를 선택하고 해당 원문으로 생성·검증 |

### 평가 범위

고정 원문 **1,525개**, 직접 검색 뷰 **5,968개**, 개발 **32문항**, 답변 평가 **178문항**, 검색 Gold **175문항**이다. 기존에 관측한 데이터의 탐색적 평가이며, 현재 결과만으로 Aspect의 성능 이득이나 모든 요구 충족을 보장하지 않는다.

### 발표 대본

오늘 소개할 최종 방법은 PARS-RF + Kiwi입니다. 수주·제안 질문에는 진행 방식, 특성, 조건처럼 서로 다른 요구가 함께 들어갑니다. 그래서 질문 전체의 검색 후보와 각 요구의 후보를 함께 사용하도록 설계했습니다. 여기서 Aspect는 단순 키워드가 아니라 원문에서 추출한 정보 요구입니다. 그래프는 업무 맥락을 약하게 보정하고, 최종 답변 근거는 실제 원문으로 제한합니다. 이 방법은 새 모델 학습이 아니라 검색과 근거 선택 절차의 설계입니다. 평가 대상은 기존 210문항 중 답변 178문항, 검색 Gold 175문항이며 독립 시험셋은 아닙니다. Aspect를 유지한다는 설계 결정과 성능상 항상 최적이라는 주장은 구분하겠습니다.

## 슬라이드 2. 알고리즘 — Aspect는 후보 발굴에, CE는 최종 선택에

### 처리 순서

1. **Aspect 추출:** Kiwi와 고정 규칙으로 원 질문의 요구를 추출하고 조건을 연결한다. 개수의 고정 상한을 두지 않는다.
2. **질문 점수 R:** 의미·BM25 관련성에 PCF·TaskFrame 그래프 보정을 반영한다.
3. **Aspect 점수 M:** 각 요구를 원문 및 직접 Fact·속성 뷰와 비교한다.
4. **후보 통합:** 질문 상위 40개와 각 Aspect 상위 20개의 합집합을 만든다. Evidence ID로 중복을 제거한다.
5. **원문 재정렬:** 원 질문과 후보 원문을 CE에 넣어 Top5를 선택한다.
6. **생성·검증:** 같은 GPT-4o mini로 원문 기반 답변을 생성하고 근거·인용을 검사한다.

### 핵심 수식

```text
H = 0.75 × 의미 관련성 + 0.25 × 정규화 BM25
g = 0.9 + 0.1 × (0.5p + 0.5t)
R = g × H
M_i = g × max(Aspect i와 직접 뷰의 유사도)
C(q) = Top40(R) ∪ Union_i[Top20(M_i)]
최종 근거 = 후보 C(q)의 원 질문–원문 CE 상위 5개
```

p는 PCF 거리 기반 점수, t는 TaskFrame 정렬 점수다. 그래프는 약한 보정이며, 그래프에 연결되지 않은 원문도 검색 대상에 남는다.

### 설계상 구분

Aspect는 후보를 추가하는 역할이다. 최종 Top5에 Aspect별 근거 하나를 강제로 배정하지 않으며 coverage 보너스·RRF·MMR을 사용하지 않는다. 답변의 사실 근거는 선택된 원문이고 그래프 라벨이나 출처 메타데이터는 추가 사실로 취급하지 않는다.

### 발표 대본

먼저 Kiwi와 고정 규칙으로 원 질문의 요구 구문을 추출하고 조건을 연결합니다. Aspect 개수의 고정 상한은 없습니다. 질문 전체에는 의미·어휘 관련성과 PCF·TaskFrame 보정을 적용해 R을 계산합니다. 각 Aspect는 원문과 직접 연결된 Fact·속성 뷰에 대해 M을 계산합니다. R 상위 40개와 각 M 상위 20개의 합집합을 만들고 중복을 제거합니다. 다음으로 원 질문과 후보 원문만 Cross-Encoder에 넣어 Top5를 선택합니다. Aspect별 근거를 강제로 하나씩 배정하거나 coverage 보너스를 주지 않습니다. 이후 동일 GPT-4o mini로 생성과 근거 검증을 수행합니다. 실제 예시 질문에서는 두 요구로 70개 후보가 생겼고, 하나의 원문이 두 요구를 함께 지지했습니다. 그래프에 연결되지 않은 원문도 제거하지 않습니다.

### 측정 조건

- 성능은 0–100 척도이며 답변 178문항·검색 Gold 175문항 기준이다. 답변 유사도는 사실 정확도가 아니다.
- 검색은 입력이 준비된 warm 평균이다. LLM 추출 시간은 검색 열에서 제외하고 온라인 응답에는 포함한다.
- 응답 평균·P95·API 비용은 동일 30문항의 신규 호출 측정이다. P95는 응답시간의 95백분위다.
- 동시성은 FullDoc 2, LightRAG 1, 나머지 8이다. 앱 캐시는 끄고 provider prompt cache는 유지·기록했다.
- API 비용은 GPT·임베딩 사용량 기반 추정이며 구축·GPU 운영 비용은 제외한다.
- LightRAG는 공유 KG 검색기 비교이며 논문 전체 재현은 아니다. FullDoc 성능에는 실패 1건도 포함한다.

### 읽어야 할 차이

Dense+CE 대비 PARS-RF + Kiwi의 Recall@5는 **73.78 → 76.90(+3.12%p)**, ROUGE-L은 **47.08 → 47.51(+0.43점)**이다. 점추정 차이이며 답변 품질의 통계적으로 확정된 우위를 뜻하지 않는다.

### 발표 대본

이 표는 핵심 베이스라인 다섯 개, 보조 베이스라인 네 개, 최종 제안 방법과 LLM 추출기 비교를 포함한 11조건입니다. 굵은 행은 최고값 표시가 아니라 최종 채택을 뜻합니다. 가장 중요한 단순 기준은 Dense+CE입니다. Recall@5는 Dense+CE 73.78에서 PARS-RF + Kiwi 76.90으로 3.12퍼센트포인트 높습니다. ROUGE-L 변화는 약 0.43점이며 통계적으로 확정된 답변 품질 우위라고 말하지 않습니다. LLM 추출은 Recall 77.18로 조금 높지만 응답시간은 4.56초에서 6.01초로 늘었습니다. 검색 시간은 warm 측정이고, 전체 응답은 같은 30문항의 신규 호출 측정입니다. 비용은 30문항 합계이며 구축·GPU 비용은 제외합니다. FullDoc과 LightRAG의 동시성 차이, 공유 KG 비교 범위, 기존 생성 실패도 해석에 포함해야 합니다.

## 슬라이드 4. 결과 해석 — Kiwi 유지와 Aspect 효과의 후속 검증

### 최종 선택

Aspect를 포함하는 **PARS-RF + Kiwi**를 최종 방법으로 유지한다. 추출기를 LLM으로 교체한 실험에서 뚜렷한 품질 우위가 확인되지 않았으며 지연·비용이 증가했다.

### 핵심 수치

| 비교 | 관측값 | 해석 |
| --- | --- | --- |
| Dense+CE → PARS-RF + Kiwi | Recall@5 +3.12%p | 검색 점추정 개선. 차이 전체를 Aspect 효과로 귀속하지 않음 |
| Kiwi → LLM 추출 | 응답 평균 +1.45초 | 4.56 → 6.01초 |
| Kiwi → LLM 추출 | API 비용 약 +15.6% | 30문항 $0.010801 → $0.012486 |
| 최종 방법 → Aspect 확장 제거 | Recall@5 76.90 → 77.95 | Aspect 추가 이득은 현재 데이터에서 입증되지 않음 |

### 함께 공개해야 하는 한계

메인 표 밖 구성요소 비교에서 Aspect 후보 확장 제거 조건이 더 높은 점수를 보였다. Kiwi 추출은 210문항 중 200문항이 단일 요구였으므로 복합 요구에서의 효과를 판단할 근거도 제한적이다. 최종 구조를 채택한 결정과 모든 조건에서의 성능 우위는 구분한다.

### 후속 검증

1. 새 문서에서 복합 요구·조건 질문을 확보한다.
2. 사람 검수로 요구 충족·조건 보존·근거 타당성을 평가한다.
3. 같은 동시성과 반복 횟수로 지연·비용을 측정한다.

현재의 기여는 요구별 후보 확장과 원문 관련성 선택을 분리한 재현 가능한 구조와 그 비교 결과다.

### 발표 대본

최종적으로 Aspect를 포함하는 PARS-RF + Kiwi를 유지합니다. 추출기만 LLM으로 바꾼 실험에서 뚜렷한 품질 이득이 확인되지 않았고 응답과 비용이 증가했기 때문입니다. 동시에 불리한 결과도 중요합니다. 메인 표 밖 구성요소 비교에서는 Aspect 후보 확장을 제거한 조건의 Recall이 77.95로 최종 방법보다 높았습니다. 따라서 Aspect 덕분에 성능이 향상되었다고 단정하지 않습니다. 실제 Kiwi 추출은 210문항 중 200문항이 한 요구였기 때문에 다중 요구에서의 효용을 판단할 자료가 부족합니다. 다음 검증은 새 문서의 복합 요구·조건 질문, 사람의 요구 충족 평가, 동일 동시성 반복 측정입니다. 현재 기여는 요구별 후보 확장과 원문 관련성 선택을 분리한 재현 가능한 구조와 비교 결과라고 정리하겠습니다.
